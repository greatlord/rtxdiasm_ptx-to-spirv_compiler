# Supported PTX ISA subset (Phase 4 prototype + Stage 6 incl. f64)

Conformance rule: anything not listed here as ✅ is rejected with a
`line N: ...` message (`ACUDA_ERROR_NOT_SUPPORTED`). The compiler never
silently mistranslates. For a chapter-by-chapter PTX ISA 9.3
done/partly/todo audit, see [`isa-coverage.md`](isa-coverage.md). `tests/ptx/vecadd_numba.ptx` (the original
numba harvest) now compiles AND launches 4096-correct via `test_driver`;
garbage input is still rejected. Reference corpus:
`tests/ptx/nb_ejit.ptx` (`.entry`), `tests/ptx/nb_f32.ptx` (`.func`).

Legend: ✅ supported · ❌ clean error · 🔶 accepted but ignored/constrained.

## 1. Source format

| Item | Status | Notes |
|---|---|---|
| Whitespace, newlines | ✅ | Free-form, C-like |
| `//` and `/* */` comments | ✅ | |
| `# ...` preprocessor lines | 🔶 | Skipped (tolerated, no macro expansion; PTX is consumed post-cpp) |
| `#include/#define/#if/#ifdef/#else/#endif/#line/#file` | 🔶 | Same: skipped as `#` lines, never expanded |

| Negative literals | ✅ | Unary `-`/`+` on int/float literals (`-1`, `-1.5`); hex `0F`/`0D` payloads with A-F letters also lex now |

## 4b. Param classification (Stage 6)

`.u64`/`.b64` params are classified by lineage (`mov`/`add.u64`/`cvta`
propagation): address use (`ld/st [...]`) vs scalar use (any other
register operand). `ACUDA_DEBUG_CLASSIFY=1` prints `classify <name> ->
<kind>`. Unused params consume a `kernelParams` slot but emit no
descriptor/push words (driver skips kind 3). When an `add` combines two
tracked lineages, the side already used as an address wins (base +
small-offset idiom). Two kernel pointers are both addresses, so the
result is a plain integer value, not a pointer: PTX defines `add/sub.u64`
of two addresses as integer arithmetic (the `stateful_neg_offset`
dead-result idiom). The backend holds a global pointer as a descriptor
plus byte offset, so that value is the offset arithmetic (raw device
addresses are not representable). Shared/global-image pairs keep their
space-coded homes and stay clean errors, as does scalar-minus-pointer
(no base to attribute). Analysis
failure can never yield an empty module (hardened after finding exactly
that bug with a real numba kernel).

## 7. Special registers and launch model

`%tid.x`, `%ntid.x`, `%ctaid.x` only (`.y/.z` rejected: 1D kernels).
`%ntid` lowers to a specialization-constant composite; `LocalSizeId`
lets each launch specialize any `blockDimX` in 1..1024 (one pipeline
per size, cached; needs `VK_KHR_maintenance4`). There is exactly one
entry point per compilation.

## 8. Diagnostics

Every failure returns `ACUDA_ERROR_NOT_SUPPORTED` (or `INVALID_VALUE`
for bad API use) plus a `line N: reason` message in `errbuf`.
The emitter additionally self-checks module structure (word-count walk)
and honors `ACUDA_DUMP_SPV=1` (writes `/tmp/acuda_debug.spv` on
emitter-bug failures), `ACUDA_DUMP_SPV_DIR=<dir>` (best-effort
`<entry>.spv` per successful compile for `spirv-dis` inspection;
long names truncated, never fails the compile) and `ACUDA_DEBUG_EMIT=1`
(section sizes). The Float64 capability/type are emitted only when f64
is actually used, so f32-only modules never require `shaderFloat64`.

Surface instructions (`suld`/`sust`/`sured`/`suq`) bind `.surfref`
parameters or `.u64` surface-object handles to Vulkan storage images
(`acuda_surface_create`, `R32ui` for byte-addressed `.b` and `Rgba32f`
for formatted `.p`; a surface used by `sured.p.add/min/max.f32` is declared
`R32f`; a surface used only by `.b64`/`sured.u64` accesses is declared
`R64ui`, format 5), with 1D/2D/3D/array accesses, b8/b16/b32/b64 loads and
stores, formatted sample stores, and add/min/max/and/or reductions
through image atomics. 64-bit `suld`/`sust`/`sured` use the native R64ui
image operations (`SPV_EXT_shader_image_int64`, `Int64ImageEXT`, plus
`Int64Atomics` for reductions) when the surface is R64ui; other surfaces
keep the two-word R32ui emulation (and 64-bit reductions there are a
clean error). `sured.p.add.f32` additionally requires `shaderImageFloat32AtomicAdd`
and an R32f surface; `sured.p.min/max.f32` use
`OpAtomicFMinEXT`/`OpAtomicFMaxEXT` and require
`shaderImageFloat32AtomicMinMax` (supported on the test GPU, while
image add is not). Handles not statically tied to one parameter
index runtime-sized per-type storage-image tables, enabling runtime
selection among live surface objects in one launch.

## 10. f64 emulation (`ACUDA_EMU_F64=1`, explicit opt-in only)

Native path is untouched when unset. When set (`1`/`true`/`yes`),
doubles demote to floats: arithmetic/`setp`/`mov` run in f32, memory
still holds 8-byte doubles converted at the boundary with integer-only
bit tricks (no Float64 capability declared, so the module loads without
`shaderFloat64`). Precision: f32-level (measured max rel err ~1e-7 on
vecadd); converts round-to-nearest-even, double denormals and
f32-subnormal results flush to signed zero. `cvt`/`mad`/`fma` with f64
stay clean errors. A loud once-per-process stderr warning marks every
demoted compile — never silent. Pinned by
`python-test/nb_f64_emu.py` (allclose + inexact + no-Float64-cap).

Driver clients get more: when the device lacks `shaderFloat64` and the
user set no explicit flag, `cuModuleGetFunction` compiles emulated
automatically (verified by forcing the feature off: 8/8 green, f64
launches exact on exactly-representable values). Native f64 stays the
default wherever the feature exists.
